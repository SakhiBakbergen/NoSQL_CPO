# Кэш расписания университета (Вариант 11)

## Описание проекта
Учебный мини-проект по дисциплине «Проектирование и применение NoSQL-технологий».
Реализован прототип подсистемы кэширования расписания университета с использованием паттерна **Cache-aside**.
Основное хранилище данных — MongoDB, кэш — Redis. Реализованы механизмы TTL (Time-To-Live) и инвалидации кэша по тегам при изменении расписания, а также проанализировано поведение устаревших данных (stale data).

## Используемые технологии
- **Java 17+**
- **MongoDB 7** (основное хранилище)
- **Redis 7** (кэш)
- **Maven** (сборка)
- **Docker / docker-compose** (развертывание баз данных)
- **JUnit 5** (тестирование)

## Архитектура и модель данных
- **MongoDB**: База `university`, коллекция `lessons`. Документ содержит поля: `_id`, `groupId`, `teacherId`, `subject`, `room`, `date`, `week`, `start`, `end`, `updatedAt`. Созданы индексы для ускорения поиска по группам, преподавателям, аудиториям и датам.
- **Redis**: Используется для кэширования списков занятий. Ключи вида `schedule:group:<id>:<week>`. Для инвалидации используются теги (Sets) вида `tag:group:<id>`.
- **Инвалидация**: При создании, обновлении или удалении занятия сбрасываются кэши, связанные со старой и новой группой/преподавателем.
